# continew-web

> 개발 중인 웹 시제품입니다. 아직 구현되지 않은 화면이 있으며, 앱 안의 기록은 브라우저 localStorage에 암호화 없이 저장됩니다. 실제 민감한 기록을 입력하지 마세요. PIN은 화면 잠금만 제공하며 브라우저 저장 데이터 자체를 보호하지 않습니다.

contiNEW 모바일 앱 프론트엔드 (React + TypeScript + Vite).
백엔드: [continew-server](https://github.com/kokohama8572/continew-server)
기준 문서: 기능명세서 v0.2

## 시작하기

```bash
npm install
npm run dev
```

## 폴더 구조

```
src/
  screens/     SCR-01~09 화면 (파일 하나가 화면 하나)
  components/  공용 컴포넌트 (Shell = 상단 공간 바 + 하단 탭)
  state/       앱 상태 (지금 열린 공간 등)
  types/       명세서 8장 데이터 모델, 6.3 요약 응답 타입
  styles/      디자인 토큰
```

## 브랜치 규칙

| 브랜치             | 용도                                                               |
| ------------------ | ------------------------------------------------------------------ |
| `main`             | 항상 돌아가는 상태. dev에서 머지                                   |

| `feat/SCR-xx-이름` | 화면 단위 작업 시 필요할 때 생성 (예: `feat/SCR-05-share-confirm`) |
| `feat/data-layer`  | 로컬 DB·모델 연결 작업 시 생성                                     |

커밋 메시지에 기능 ID를 붙입니다. 예: `feat(SCR-05): 공유 확인 화면 작성자 표기 비움 기본값 (F-03-3)`

## 지킬 것 (명세서 설계 원칙)

- 작성자 표기·확인 표기는 미리 채우지 않는다 (원칙2)
- 공유 확인 화면을 건너뛰는 길을 만들지 않는다 (F-03-3)
- 공용 항목에는 space id를 저장하지 않는다 (8장)
- 기록 빈도, 확인 여부를 점수·그래프로 보여주거나 재촉하지 않는다 (원칙6)
- 화면 문구에 '교대', '전환', '인격' 같은 임상 용어를 쓰지 않는다 (2장)

## 연동 전 개발 방식

백엔드 연동 전에는 `src/mocks/seed.ts`의 가상 데이터로 화면을 만들고, 상태는 `src/state/`의 reducer와 브라우저 localStorage에 저장합니다.
개발 중 데이터를 되돌리려면 콘솔에서 `localStorage.removeItem('continew:v2')` 후 새로고침합니다.
서버를 붙일 때는 `src/state/store.tsx`의 저장·불러오기 부분만 바꿉니다.

## 먼저 알아둘 코드

- `src/copy.ts`: 명세서에 정해진 고정 문구(공간 안내, 공개 범위, 요약 안내 등). 화면에 직접 쓰지 말고 가져다 쓴다.
- `src/state/reducer.ts`: 작성자 표기 비움 시 게시 불가, 공간 id 미저장 같은 명세서 규칙이 여기 들어 있고 `reducer.test.ts`가 지킨다.
- `src/state/selectors.ts`: 메모는 열린 공간 id로만 읽고, 게시판은 F-03-5 순서로 정렬한다.

## AI 요약 API 연동 (`src/api/`)

백엔드 `POST /api/v1/summaries` 연동 코드가 들어 있습니다. 서버가 하는 일은 공용 영역 글 요약 하나뿐이고, 나머지 데이터는 기기에 저장합니다.

| 파일              | 하는 일                                                                                  |
| ----------------- | ---------------------------------------------------------------------------------------- |
| `types.ts`        | 요청·응답·에러 코드 타입, 상한 상수 (300개, 25초, 3초)                                   |
| `buildRequest.ts` | 게시판·대화 글만 `items`로 변환. 메모는 읽지 않음. 3개 이하 / 300개 초과 판정, 기간 계산 |
| `pseudonym.ts`    | 작성자 표기 ↔ 작성자1·2 가명화·복원                                                      |
| `summary.ts`      | 요청 함수(25초 타임아웃·취소), 에러별 문구, 요약 캐시                                    |
| `mockSummary.ts`  | 서버 없이 쓰는 가짜 응답                                                                 |
| `useSummary.ts`   | SCR-08에서 쓰는 훅. 버튼 잠금, 3초 후 취소, 캐시, 복원                                   |
| `format.ts`       | 날짜·원문 병기 문구, 원문 id → 종류                                                      |

**서버 없이 개발:** `.env.example`을 `.env.local`로 복사하면 `VITE_USE_MOCK_SUMMARY=true`로 가짜 응답이 나옵니다.
**서버 붙이기:** 값을 `false`로 바꾸고 continew-server를 띄우면 vite가 `/api`를 `localhost:8080`으로 넘겨 CORS를 피합니다. 배포나 폰 테스트처럼 다른 주소에서 열 땐 서버 담당에게 허용 주소를 요청해야 합니다.

AI 요약 설정이 꺼져 있으면 `useSummary().run`은 아무것도 하지 않습니다. 설정을 끄면 캐시가 즉시 지워집니다.

## 기기 변경용 백업·복원

설정에서 전체 앱 기록을 암호화 파일로 내려받고 새 기기에서 복원할 수 있습니다. 파일은 PBKDF2-SHA-256(310,000회)으로 만든 키와 AES-256-GCM으로 암호화합니다. 백업 비밀번호는 서버나 앱에 저장하지 않으므로 파일과 비밀번호를 각각 보관해야 합니다. 복원은 현재 기록 전체를 교체하며, 화면에서 명시적으로 확인한 뒤 실행합니다.

현재 백엔드 API는 요약 기능만 담당하므로 이 백업 기능에는 서버 변경이 필요하지 않습니다. 기능 명세서의 전체 백업·복원(F-09-2·3)을 P1에서 MVP로 앞당긴 결정은 팀 문서에도 반영해야 합니다. **복원 뒤 앱 안의 기록은 다시 암호화되지 않은 localStorage에 저장됩니다.** 실제 사용자 기록을 다루기 전 기기 내 저장소 암호화와 보안 검토가 필요합니다.

개발 중에는 공용 영역 맨 아래 "개발용" 박스로 AI 요약 켜짐/꺼짐을 바꿀 수 있습니다(설정 화면의 동의 절차가 생기면 삭제).
폰트는 Pretendard(`pretendard` 패키지), 아이콘은 `lucide-react`입니다.
